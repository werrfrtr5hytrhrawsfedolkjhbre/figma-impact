# DSH 变更影响分析插件 · 总览

> 一个跑在 Figma 里的纯前端插件：改一处设计，自动找出"还有哪些地方会受影响"，
> 让 AI 解释原因、给出可执行的修改指令，由人逐条确认后应用。

- 文件：`manifest.json` / `code.js` / `ui.html`
- 技术栈：Figma Plugin API + 浏览器内直接调大模型（无后端）
- 网络：`api.deepseek.com`、`api.openai.com`（manifest 白名单）

---

## 一、它能做什么

### 1. 扫描文件，建立依赖图

遍历全部页面，抽出四类关系：

| 边 | 来源 | 用途 |
|---|---|---|
| `prototype` | 交互（Reaction）里指向画板（Node）的动作 | 页面流转影响 |
| `instance` | 实例 → 主组件 | 改组件影响所有引用处 |
| `child` | 父子结构 | 上下游可视化 |
| `style` | 节点引用的 text/fill/stroke style | 仅统计，不参与影响计算 |

同时统计：节点数、原型反应对象数、指向画板的导航数、其它动作数（设置变量/返回/关闭等）。
**只读**，不改设计稿。

### 2. 影响分析（一条链路，两个按钮共用）

| 入口 | 输入 | 产出 |
|---|---|---|
| **① 影响节点显示** | 锚点 + 范围 | 结构影响集合（图传播 + 同容器），不含语义 |
| **② AI 影响分析** | ①的集合 + 变更需求 +（文本）语义等级 | ①的集合 ∪ 语义命中 + AI 说明 |
| **③ 影响节点修改建议** | ②的集合（没跑②就用①） | 针对这批节点的可执行指令 |

- 三级：直接（1 跳）/ 间接（2 跳）/ 潜在（3 跳）
- 每条标注来源：`图` / `结构` / `语义`
- 语义等级三档：**严**（只留 high）/ **中**（默认，medium+high）/ **宽**（全留）
- 语义条目默认**不勾选**，必须人工挑；上限 200 条，稠密图截断

### 3. 画布标注（不碰原设计）

在页面顶层创建两套普通图层：

```
[DSH] 影响范围 · S1ABC   ← 彩色描边 + 编号，始终显示
[DSH] 建议气泡 · S1ABC   ← 编号 + 理由文字，可单独隐藏
```

- 颜色分级：红 / 橙 / 黄，4px 描边外扩 4px（避开选中蓝框）
- 跨页：按节点所在页面分别建层
- 气泡内容 = `图理由 · AI：语义说明`
- **协作者不开插件也能用图层眼睛隐藏气泡层**
- 关闭插件自动清理；评审中重开会按会话记录重建

### 4. 评审状态机

`IDLE → REVIEWING → SETTLING → IDLE`

| 阶段 | 行为 |
|---|---|
| 开始评审 | 冻结分析、记录每个标记节点的指纹 |
| 评审中 | `documentchange` 只记录不重算；他人可见"评审中 · 张三" |
| 结束评审 | **仅发起者**；对账（改了/没改/被删）+ **越界审计**（未标记却被改） |

- 会话存 `figma.root` 插件数据，随文件同步
- 状态、发起者、时间对所有协作者一致

### 5. 修改建议 → 校验 → 应用 → 撤销

AI 输出结构化指令，代码逐条校验后由用户勾选应用：

| kind | 作用 | 前置条件 |
|---|---|---|
| `text` | 改文案（整段或**局部替换**） | from 必须是当前文本中真实存在的片段 |
| `variant` / `boolean` | 改实例属性 | 目标是实例 |
| `visible` | 显隐 | — |
| `fill` | 纯色填充 `#RRGGBB` | 首个填充是 SOLID |
| `opacity` / `radius` | 不透明度 / 圆角 | — |
| `font` | 字号 / 行高 / 字体（支持 `range` 局部） | 文本节点；换字体只加载**目标字体** |
| `size` | 宽高 `320x48` | 可 resize |
| `spacing` | auto-layout 间距 | 必须是 auto-layout 容器 |

**四道护栏**：类型白名单 → id 必须在清单内 → `from` 校验（属性类会自动按实际值校正）→ `commitUndo()` 整批撤销。
**回滚**：记录 `before` 原文/原值，「回滚本次应用」可精确还原，不依赖 Figma 撤销栈。

### 6. 局部修改（range）

想只改句中的词，用括号包住即可：

| 写法 | 效果 |
|---|---|
| `把【机制】改成宋体` | 只改"机制"两个字（`setRangeFontName/FontSize`） |
| `把[机制]改成宋体` / `“机制”` | 同上 |
| `把机制改成宋体` | 整段修改 |

描述里只有一个括号片段时，字体/填充类建议会**自动限定**到该片段。

### 7. AI 接入（可切换服务商）

| 服务商 | Base | 测试接口 |
|---|---|---|
| DeepSeek | `api.deepseek.com` | `/user/balance`（查余额） |
| OpenAI | `api.openai.com` | `/v1/models`（列模型） |
| 自定义 | 自填（OpenAI 兼容） | `/v1/models` |

- Key / Base / 模型**按服务商分开存**（`figma.clientStorage`）
- JSON 模式 + `temperature: 0`，提高可复现性
- CORS 已验证：两家都回显 `Origin: null`，插件可直连

### 8. 交互细节

- 范围四档同时作用于**分析 / 标记 / 建议**：仅选中节点（只锚点）/ 相关范围（图传播+同容器，文本语义限本页）/ 同组件实例 / 整个文件（语义全文件）
- 影响子栏目：全部 / 直接 / 间接 / 潜在，切换时**画布标记同步过滤**
- 「回到锚点」：点列表查看后一键回到分析起点
- 变更描述历史：最近 6 条，去重置顶，本机存储
- 自动清空：应用完全部变更 / 评审结算后清空（内容仍在历史里）
- 未选中节点时，三个主按钮全部禁用

## 二、它不能做什么

### 结构层面

- **纯 PPT / 无跳转文件**：没有 `prototype` 边、没有组件实例时，图传播结果为空（可用"文本连锁"兜底）
- **跨文件**：只看当前文件，库组件在别的文件里取不到主组件
- **样式影响**：`style` 边只统计，不参与影响计算
- **组件定义的默认值**：`componentPropertyDefinitions` 改不了，只能改实例上的值
- **位置属性**：`x / y` 刻意不支持（auto-layout 会覆盖，收益低、破坏性高）

### 应用层面

- **实例内部**：`INSTANCE` 的子图层基本只读，写入会失败（逐条回报）
- **混合字体/字号**：整段改会被拒，必须用 `range` 改局部
- **局部修改字体/字号**（range）：需要这一段**当前字体也能加载**——这是 Figma 拆分文本的前置条件，否则报“当前字体不可用”
- **整段换字体**：只需加载目标字体，原字体缺失也能换
- **整段改字号/行高**：需要加载当前字体
- **auto-layout 子节点**：改尺寸/位置会被布局重排吞掉

### AI 层面

- **不保证召回**：图传播只认已建模的边；关键词匹配只是近似，"含关键词"档会有噪声
- **不做向量检索**：没有 embedding / 语义相似度，只有精确匹配 + 关键词
- **不保证稳定**：同 prompt 多次调用颗粒度可能不同；`temperature: 0` 只是降低波动
- **不能替代判断**：所有建议必须人工勾选，从不自动应用

### 生命周期

- **没有后台守护**：插件关闭即失效，改动记录只在面板打开时收集
- **越界审计依赖日志**：全程没人开插件时，只能靠指纹对账覆盖"标记节点"，查不出"越界改动"
- **关闭即清标记**：临时标注不会留在文件里；需要长期保留得手动导出

## 三、它是怎么迭代出来的

### 阶段 1：先有图（M0）

从"扫描 + 列关系"做起：页面跳转、组件使用、上下游。
**关键决策**：先把结构摸清楚，再谈智能。

### 阶段 2：图能算影响（M1）

双向 BFS 三跳分级 + 画布描边。
早期三个按钮（1 跳/2 跳/3 跳）后来改名为"直接/间接/潜在"，再后来合并成一个按钮 + 子栏目 —— 因为**数据本来一次就全算了，三个按钮只是视角**。

### 阶段 3：AI 进来，但被约束（M2）

最初让 AI 从文档摘要里"挑影响区域"，结果和按钮结果完全对不上（FAQ 页被误判）。
**转折点**：明确"**图决定是谁，AI 决定为什么**"——AI 不再新增节点，只给已有影响节点写说明；两个入口产出同一份集合。

### 阶段 4：标记要能协作（M2.5）

- 气泡拆成独立图层 → 协作者不开插件也能隐藏
- 跨页标记：按节点所在页分别建层
- 关闭清理 + 评审中重建

### 阶段 5：评审状态机（M3）

分析会随文档变化而漂移，所以引入"冻结-对账"：
开始评审时记录指纹 → 评审期只记录改动 → 结算时对账 + 越界审计。

### 阶段 6：从"建议"到"能落地"（M4）

第一版只支持三种操作，且指到"组件本体"就卡死。
迭代补上了：

1. 组件本体 → **自动展开成所有实例**
2. 支持布尔属性（开关默认值其实是 BOOLEAN，不是变体）
3. `from` 校验 + 预览勾选 + `commitUndo` 整批撤销
4. 一键回滚（记录 `from` / `before`，不依赖撤销栈）
5. 过滤"已经是目标状态"的空操作

### 阶段 7：把"文本"当一等公民

发现 PPT 场景根本没有依赖图，于是加入**文本连锁**：
完全相同 → 机械同步；含关键词 → 交给 AI 判断是否改写。
同时放宽文本编辑：支持局部替换、长文本、`range` 局部字体。

### 阶段 8：基础属性与工程化打磨

- 六类基础属性（fill / opacity / radius / font / size / spacing）
- 字体别名映射（宋体→SimSun）+ 目标字体模糊匹配
- `from` 自动校正（模型串行同名节点时不再整条作废）
- 文本复制 bug（片段替换 vs 整段替换）
- 范围过滤穿透到文本连锁
- 界面重组：AI 接入收纳、按钮合并、提示与 tooltip、变更描述历史
- 一次编码事故后，`ui.html` 整体重写

## 四、沉淀下来的设计原则

1. **确定性优先**：能用图算的，不问模型；模型只补充"为什么"和"改什么"。
2. **精确约束模糊**：AI 不能新增影响节点，只能在既有集合内活动。
3. **单一事实来源**：影响集合只有一份，建议的候选池也从它派生（必要时按锚点重算）。
4. **人批准制**：所有写入都要勾选；先预览 diff，再一次性应用。
5. **可逆**：一批改动合成一步撤销；另有基于记录的回滚，不依赖 Figma 撤销栈。
6. **可解释**：每条影响标来源（图/结构/文本），每条建议标理由与校验结果。

## 五、快速上手

1. Figma → Plugins → Development → Import plugin from manifest → 选 `manifest.json`
2. 打开插件（自动扫描）
3. 选中变更源节点
   - 图形/组件 → 「影响节点显示」
   - 文本 → 同样点「影响节点显示」拿到**结构**影响；语义相关节点在「AI 影响分析」里按需求检索
4. 写变更描述（用【】标出局部片段）
5. 「AI 影响分析」看语义说明 / 「影响节点修改建议」出可执行指令
6. 勾选 → 应用 → 不满意就「回滚本次应用」或 Ctrl+Z
7. 团队协作：开始评审 → 大家改 → 发起者结束评审 → 看对账与越界报告

## 六、已知限制速查

| 场景 | 现状 |
|---|---|
| PPT 无跳转、无组件 | 图传播为空，靠文本连锁 |
| 实例内部节点 | 写入失败（只读） |
| 局部改字体/字号 | 需要当前字体也可用；整段换字体只需目标字体 |
| 段落内混合样式 | 必须用 range 改局部 |
| 组件定义默认值 | 不支持 |
| 位置 x/y | 不支持（约定） |
| 关闭插件后的改动 | 进不了日志；标记也被清理 |
| AI 联网 | OpenAI 需代理/系统 VPN；manifest 需含该域名 |
